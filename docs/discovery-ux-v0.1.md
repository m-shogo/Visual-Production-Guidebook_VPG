# 発見体験（トリアージ動線・検索）設計 v0.1

2026-09-21の議論で決定した2点：初心者向けトリアージ動線の設計と、チャット併用の可否。

## 1. なぜトリアージ動線が要るか

カタログが増える（124〜500語級になりうる、[decisions-log.md](./decisions-log.md)参照）と、用語も技法も持たない初心者に「全部見てください」は成立しない。かといって検索窓だけを置いても、言葉にできない人は最初の一歩が出せない（[review-2026-09-20.md](./review-2026-09-20.md)以降の議論で確認した「コールドスタート問題」）。

## 2. トリアージ動線の設計

Pinterestのオンボーディングに近い、**段階的な絞り込み**を採用する。

### Step 1: 少数の、視覚的に大きく異なる例を見せる

- カテゴリを横断して6〜9件、印象が大きく異なるものを選んで提示する（例: 静かで親密なPush In系、派手で高速なBeat Cut系、ノスタルジックなFilm Grain系…）
- 「気になるものを選んでください（複数可）」

### Step 2: 選ばれたものの`impression_tags`/`categories`を手がかりに、似たものを追加提示

- Step 1で選ばれたエントリの`impression_tags`を集計し、重なりの多いタグを持つ他のエントリを次に見せる
- これを1〜2回繰り返す

### Step 3: 個別のTechnique/Recipe詳細へ着地

- 十分絞り込まれたら、一覧ではなく個別の詳細カード（one_liner, why_it_works, ai_prompt_fragment, software_instructions等）を見せる

### 既に用語を知っている人向けの並行導線

トリアージは初心者専用ではなく、**知っている人は素通りできる**必要がある。並行して常に「カテゴリから探す」「名前で検索する」の導線を残す。design-v0.1 §7の3つの入口（見た目／やりたいこと／名前）をそのまま踏襲する。

## 3. チャット併用の可否

**結論：フルのLLMチャットボットは今は作らない。Intent語彙に対する軽量なテキスト検索窓で十分。**

### 理由

- 「したいことを言葉にできる人」には検索窓が要る。しかしこれはLLMである必要はない。`data/intents/*.yaml`の`label_ja`/`label_en`/`description`と、Technique/Recipeの`name_ja`/`name_en`/`synonyms`/`one_liner`に対する**単純なキーワード一致検索**で、最初のバージョンは十分に機能するはず
- フルLLMチャットは開発・運用コストが高く（API費用、プロンプト設計、誤答対策）、しかも前回議論した通り「レビュー済みで精度保証されたデータ」こそが一般的なLLM chatに対する差別化ポイントだった。チャットボット化すると、その差別化が薄まるリスクがある
- 将来、キーワード一致では拾いきれない曖昧な入力（「なんかこう、切ない感じ」等）が増えてきたら、その時点でLLMベースの意味検索を追加する。**最初から作らない。**

### 検索窓の仕様（最小版）

- 入力文字列を、Intent.label_ja / label_en / Technique.name_ja / name_en / synonyms / one_liner に対して部分一致検索する
- ヒットしたIntentがあれば、その`related_techniques`（重み順）を提示する
- ヒットしたTechnique/Recipeがあれば、そのまま詳細へ
